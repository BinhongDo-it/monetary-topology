## 1. What the loop needs, field by field

`b8_fannie_slice.md` §3.1 fixes `ω` as the log ratio of the present value of the
remaining contractual obligation. That requires, **on both sides of a modification
and for the same loan**:

| field | used for | side |
|---|---|---|
| current interest rate | the payment stream | both |
| current actual UPB | the principal | both |
| remaining months to maturity | the horizon | both |
| delinquency status | the tier index `q` | path |
| modification flag | the `delinquent → modified` edge | path |
| zero balance code and its effective date | the hole: who exits to liquidation instead | §5's B8-5 |
| principal forgiveness amount | forgiveness, which is not deferral | `ω` |
| interest-bearing vs non-interest-bearing UPB | deferral, which is not forgiveness | `ω` |

From the acquisition side, for the agent classes of §5: credit score band, LTV,
DTI, first-time buyer flag, occupancy, property state, loan purpose, channel.

**The two UPB fields are not interchangeable and the check must confirm both are
present.** `b8_fannie_slice.md` §3.1 counts deferred principal at zero interest to
maturity and does **not** write it off; if only a single UPB field exists, that
distinction cannot be made and the `ω` construction has to be rewritten before
anything is computed.

## 2. The check that goes first, because it can change §11's branch table

**Is the modification programme identifiable?**

`b8_fannie_slice.md` §5 restricts B8-4 to the **Flex Modification** sub-population,
and the entire discriminating power of B8-4 rests on that restriction: Flex Mod is
rules-based, so *"the servicer priced the risk"* does not explain class dispersion
inside it. Outside it, B8-4 is reported but is **not** discriminating.

**A `modification flag` records that a loan was modified. It does not record under
which programme.** Whether the public file carries a programme identifier, or any
field from which HAMP-era and Flex-era modifications can be separated other than by
date, **is not known to this project** and is the first thing to establish.

Three outcomes, mapped here rather than after looking:

| finding | consequence |
|---|---|
| a programme field exists | B8-4 runs as registered |
| no programme field, but the eras are cleanly separated by date (HAMP wound down, Flex began) | B8-4 runs on a **date-defined proxy**, and the proxy is labelled as one wherever B8-4 is quoted. Discipline 6 applies: **the proxy's validity is checked before it is used**, by confirming that modification terms inside the Flex window actually cluster on a posted benchmark rather than dispersing with borrower risk |
| neither | **B8-4 loses its discriminating restriction.** It is demoted to a reported association, and `b8_fannie_slice.md` §11's first branch (B8-3 and B8-4 both pass → subprime auto ABS) becomes unreachable as written. §11 is then re-registered **before** B8 runs, not after |

**This ordering is the point of the section.** Discovering it after B8-4 has run
would mean choosing the branch table with the answer in hand.

## 3. The field-completeness audit proper

Sample: one acquisition and performance pair from each of several vintages, chosen
to span `b8_fannie_slice.md` §6's four windows. **Vintages are chosen by window
coverage, not by convenience, and the list is written down before retrieval.**

| # | check | terminates the stage if |
|---|---|---|
| **C1** | for loans where `modification flag` first turns Y, are rate, UPB and remaining maturity populated in the month **before** and the month **after** | the populated rate is low in any window. Report **per vintage**, not pooled: a field that appears in 2015 and not in 2009 kills one window and not the stage |
| **C2** | is the modification month identifiable, that is does the flag turn Y once and stay Y | the flag is not monotone and no other field dates the event |
| **C3** | do loans traverse the **full triangle**: current → delinquent → modified → current, with the post-modification return to a performing delinquency status observable | the third leg is unobservable, in which case the loop does not close and there is no stage |
| **C4** | **count** the loans completing the triangle, per window | the count is small. Conclusion 28's event-count wall applies: a discrete-event claim must count its events first, and no estimator repairs too few |
| **C5** | do loans that cure **without** modification exist in quantity | they do not, in which case **B8-0a has no sample** and the gate cannot be run, and per §8 nothing after the gate may be read |
| **C6** | are the two UPB fields both present, per §1 | only one exists, in which case `ω` is rewritten before anything is computed |
| **C7** | are the acquisition-side class fields present and populated for the loans that complete the triangle | they are missing, in which case B8-4 and B8-5 have no agent index and B8 collapses to B8-1 and B8-2 |

**C4 and C5 are counts, not rates, and they are reported as counts.** This project
has been stopped by an event-count wall once already and the diagnosis was that no
estimator could have saved it.

## 4. Retrieval, which is its own open question

Fannie's Single-Family Loan Performance data is published free, and access is
gated by registration and acceptance of a licence rather than by payment. **Whether
that gate can be scripted, and whether the licence permits the derived series to be
kept in this repository's `data/raw/`, is not established and must be read from the
licence rather than assumed.**

If the download cannot be scripted, this repository's fetch convention (resumable,
truncation-detecting, manifest with content hash, never deletes) applies to the
**post-download** handling instead, and that departure is recorded in
`data/SOURCES.md` rather than left implicit.

**Freddie Mac is a separate layout and is out of scope for this check.**
`b8_fannie_slice.md` §7 already fixes that Freddie is a distinct arm with its own
record, not a sample extension.

## 5. One item closed while writing this check: NMDB

`b1_theorem.md`'s Corollary 2 scoping block left an open question:

> **Whether NMDB links a borrower across successive loans is an availability
> question and is not settled here.**

**On what this repository holds, the answer is no.** `data/raw/nmdb/` contains
`nmdb_new_national.csv`, `nmdb_outstanding_national.csv` and
`nmdb_outstanding_states.csv`, 18 KB, 30 KB and 1.4 MB. Those are FHFA's published
**aggregate** statistics, and `data/fetch_nmdb.py`'s own docstring says it retrieves
the aggregate series for stage B2 loop B. **There is no loan-level NMDB here and the
loan-level product is restricted-use rather than downloadable.**

So NMDB does not reach the slice summand on anything obtainable, and the
borrower-linked panel candidate in Corollary 2's scoping block is **CRISM or
nothing**, at a price. This does not affect B8, whose entire cycle happens inside a
single loan and therefore needs no borrower linkage at all. **It affects the
alternative carriers, and it is recorded so the question is not re-opened as though
it were unexamined.**

## 6. What this check cannot decide

**It cannot decide whether `ω` is well constructed.** That is
`b8_fannie_slice.md` §10 step 1, it is paper work, and §3.2 is where a stage of this
shape goes wrong. A file that carries every field in §1 is still no guarantee that
the delinquency leg has been defined without padding.

**It cannot decide whether the loop sum is non-zero.** That is B8-1 and it is
downstream of everything here.

## 6.2.3 C8-1c：注册

**问题**：C8-1a 那 1% 来自哪里。两个候选，修法不同。

| 候选 | 机制 | 修法 |
|---|---|---|
| **额外还款加每月重算月供** | 合同月供放款时钉死，代码每月按当期余额重算。历史上任何一次多还都让重算值低于合同值，缺口被 `(1+i)ⁿ` 放大。闭式 `比值 = 1 + d·(1+i)ⁿ` | `V` 与 `V̂` 把合同月供作为逐段 carry 的状态量 |
| **期限差一个月** | 真实摊还基数是 `17 − 1` 而代码用 `17` | `V̂` 用 `17 − 1`，不需要任何逐贷款状态 |

**已经用 C8 现有的表否掉的**：按实际天数计息（会让 p10 低于 1.00，实测 1.00）；
字段位置错（要让 25% 的行精确落进 [0.995, 1.005]，9、12、17 必须全对，
**一个错列造不出 25% 的点质量**，这比 C0b 的锚点是更强的确认）；
`sched_principal` 公式错（手算摊还表上干净贷款精确读 1.0000）；
`quantiles` 有偏（逐行读过，取下中位数，标准定义）。
利率印三位小数与 UPB 分转整都是亚箱噪声且方向对称。
期限差一个月在 6–7% 那三档上被它们自己的 p10 否掉（该候选预测 p10 读 1.01），
**在任何一档上都造不出 p75 的 1.10–1.25 与 p90 的 2.00**，故至多是次要成分。

**脚本**：`experiments/b8_c8_1c_contract_payment.py`，已过 `--selftest` 与合成档
端到端验证，未在真档上跑。**不动 `b8_c8_arithmetic.py`。**

**判别式，跑前钉死**：§3 那张「下界月供 / 重算月供」的表。期限差一个月的话，
合同月供固定，隐含月供恒等于它，段内完美水平，§2 也会塌到 1.00，
**但 §3 会读出紧贴 1.005–1.007 的窄带，「精确读 1.000」的比例接近零**。
额外还款的话，§3 读出**在 1.000 的大质量加一条向上重尾**。两个形状不可能搞混。
其余三条读法在裁定件 §7。

**C8-1d，注册而未跑**：下界估计的是借款人习惯支付的水平月供，一个每月都把还款凑成
同一个整数的借款人分不出来。分开需要放款侧字段，而那些位置**不在 C0b 确认的锚点表里**,
须按 C0b 的方式由行为挣得识别，不得凭 layout 文档命名。**不影响 C8-1c 问的问题。**

# 6.2.4 C8-1c 实跑（min 下界版）：四处缺陷，一条结论

**两档全扫，2002Q1 与 2019Q1，5,445 万行。** 脚本

## 6.2.4.1 一条能读的结论：期限差一个月，死了

旧约定（每月重算月供）下，比值**精确落在 1.000**（±0.0005）的月份份额：
2002Q1 是 **0.3311**（10,725,900 / 32,391,295），2019Q1 是 **0.3975**
（3,359,802 / 8,451,832）。该候选预测 6.5% 票面在 n ≤ 480 的每一点上都 ≥ 1.0059，
即**精确 1.000 的份额接近零**。实测三分之一到五分之二。**出局。**
这一行跑在全样本上，不受下面四处缺陷影响。

连带：**摊还模型对三分之一到五分之二的安静月份是精确对的，对其余是错的。**
C8-1a 那个 1.01 是混合，不是全体位移。

## 6.2.4.2 四处缺陷，全在估计量与记账，与数据无关

| # | 缺陷 | 证据 |
|---|---|---|
| **D1** | `min` 下界不稳健 | §3 的 `下界 / 重算` 读 p25 = **0.80** 与 **0.75**。在被检假设下下界就是合同月供，**不可能低于重算值**。段内一个平坦 UPB 或只付息月份就能打穿整段 |
| **D2** | 静默丢样 | `s_new > 0` 这道守卫丢掉 **15,063,560（46.5%）** 与 **2,901,056（34.3%）** 个月份，D1 的直接后果，**未计数未报告**。违反 `b8_fannie_slice.md` §7 的逐臂计数规矩 |
| **D3** | §2 两列不在同一批月份上 | 标题写着 identical months，实际旧列跑 32,391,295、新列跑 17,327,735。换成绝对数：2002Q1 新约定精确 1.000 是 9,950,056，比旧约定的 10,725,900 **少 775,844**，那个 0.3311 → 0.5742 的「提升」一大半是分母掉一半掉出来的 |
| **D4** | §3 读错位置 | 缺口一段只读一次，取剩余期限最长那一行，即段内**最早**的月份，也就是累积多还**最小**的时刻。要找的向上尾巴被按构造压平 |

**结论：诊断既未确认也未推翻，原因在估计量不在数据。** 修法进 §6.2.5。

## 6.2.5.4 跨载体：Freddie 上量到「低于簇」的一个候选成分

**加于 2026-08-16，来源 `docs/b10_freddie_availability.md` §13·1。
本节不改本站任何判据、任何注册文字、任何数。它只把一个数放进 6.2.5.3 那个开着的问题旁边。**

**先说清楚归属**：`min` 下界不稳健这件事，**本站 §6.2.4.2 的 D1 先发现，并且已经修**
（换成众数簇）。D1 逐字写着「段内一个平坦 UPB 或**只付息月份**就能打穿整段」。
B10 在 Freddie 上独立撞到同一现象，**那是复现不是发现**，
但它把 D1 那句话里的机制**量了出来**，而本站当时没有量。

Freddie sample 全 28 档、1,025,824 个过闸段，2007 档的逐月扫描：

| 量 | 值 |
|---|---|
| 月差总数 | 1,618,044 |
| **UPB 与上月完全相同的月** | **84,275（5.208%）** |
| 这些月的 `P(t) / P_contract` | p10 0.5908，**p50 0.8086**，p90 0.8507 |
| 61+ 个月的段里，最小值恰好落在这样一个月上的 | **61.73%** |

`0.8086` 就是一笔三十年贷款在生命早中期的**利息占月供的比例**：UPB 不动，
`P(t) = UPB × 利率/1200`，只剩利息那一项。

**为什么这可能是 §6.2.5.3 那 8.8% 到 8.9% 的一部分**：
一个 UPB 未更新的月按构造就落在众数簇**下方**，而它在 Freddie 上占 5.2% 的月份。
本站的「低于簇」是 8.8% 到 8.9%。**两个数同量级。**

**这与本站已经否掉的那条不是同一条。** §6.2.5.3 查的是**「众数低于当月利息」的段**
（1.8% / 1.3%），那是段级的、问众数本身的位置；这里说的是**月级的、UPB 未变的那些月**，
它们的 `P` 精确等于当月利息，而段的众数可以完全正常。**两个统计量不重叠。**

**可做的一步，零下载**：在 Fannie 上直接数 `UPB_t == UPB_{t-1}` 的安静月占比，
以及它们落在簇下方的比例。若能吃掉 8.8% 里的大部分，第三个机制就得名了；
若吃不掉，剩下的那部分是更干净的未知，因为一个已知成分被扣掉了。
**这一步不改本站任何判据，产物是一张计数表。**

**限定**：Freddie 与 Fannie 是两家的报送实践，5.208% 不得直接搬到 Fannie 上当预期值。
**本节提供的是一个待查的候选与一条数它的方法，不是一个读数。**

# 6.3 核心表：一次解析，以及全年份下载前必须先解决的事

**注册在这里，全文与实测在 `claude-docs/B8_核心表与全年份扩展_v1.md`。**
代码 `experiments/b8_core.py`（build / status / verify / selftest 四个子命令）。

## 6.3.1 为什么

实测（合成档，看倍数不看绝对值）：`line.split(b"|")` 全 113 字段 0.21 M 行/秒；
`maxsplit=108` 只快 6%；`pandas.read_csv` 带 `usecols` **反而慢四倍**（C parser 照样切完
113 个字段还多建一层 Python 对象）。每段的 Python 活是每个安静月份 0.49 微秒。
**解析占 93%，分段与算术占 7%。**

**比速度更重要的理由**：三个脚本各自手写过同一个 quiet 过滤器。
一次抄漏，三份结果就不再可比，**而所有计数量都会保持合理、所有闸都会照常通过**。
那是 A21 的形状与 `MEASUREMENT.md` 第八种失败模式。`b8_core.py` 的 `quiet_pairs()`
是唯一一份；要别的过滤器的站另写函数，**不许改这一个**。

写共享版时抓到两处手写版之间已存在的歧义，两处都已按手写版的语义钉死：
`mod_flag` 必须按布尔 `== b"Y"` 比（`N` 与空白算相等，直接比字节会悄悄缩小样本）；
`delinq` 存成整数后，位数不等于二的纯数字串映射到 253 而非其整数值，
使 `delinq == 0` 精确等价于 `字段.strip() == b"00"`。

## 6.3.2 落地的（第零档与第一档）

按档并行（`ProcessPoolExecutor`，墙钟约等于最大那一档）；逐列窄类型二进制加 manifest
（源 zip 的 CRC 与大小、行数、贷款数、字段位置表、dtype、字节序，对不上拒绝加载）；
**逐行列与逐贷款列分开**，class 字段挪出行轴。金额存分、利率存千分之一个百分点、
日期存自 1990-01 起的月序，比较是精确整数比较。
**未识别的 41、49、109–113 一个都不在表里**，C0b 的告诫管着。

| 量 | 值 |
|---|---|
| 每行 | 37 字节 |
| 六个档核心表 | 约 6.3 GB（源 zip 3.1 GB，解压 46.9 GB） |
| 建表 | 单进程 29.5 分钟，**六路并行约 7.4 分钟** |
| 之后每个问题 | 1.7 亿行 78 秒，单档约 20 秒（今天是 13.3 分钟的裸解析） |

验收三道：`selftest`（造带全部边缘的合成档，**逐对逐段**对比参考状态机，不碰真档）、
`verify`（重读源 zip 头部逐字段比，**查不了的缓存不算证据**）、`status`。

**未做**：三个实验脚本还没改成读核心表。改的时候**必须逐位复现**现有结果，
那是 R01 与 `SESSION_INIT.md` 教训四。

## 6.3.3 注册未实现的（第二档），触发条件是全年份下载

按现有六档外推，全部约 100 个收购季、约 **29 亿行**。
**这个数是外推，下载前必须按 Fannie 自己的文件清单核实，不要按它做预算。**

稠密格式在那个规模是 **约 107 GB**，16 路并行建表约 31 分钟（解析本身 8.4 小时），
全量扫一个问题约 22 分钟。**并行已经解决了建表时间，盘与扫描带宽才是问题**，
而扫描是内存带宽受限的，所以换编码同时解决两者。目标 36 → **4 到 6 字节/行**，
总量 **约 15 GB**，扫描时间同比例下降。

逐列改法：`loan_age`/`rem_legal`/`period` 是贷款内精确等差，存起值加长度加例外（省 6）；
`rem_matur` 由 `rem_legal` 推（省 2）；`mat_date` 与 `rate` 贷款内恒定只在修改时移动，
游程编码（省 4）；`delinq`/`mod_flag`/`zero_bal`/`assist`/`adr`/`adr_count` 近乎恒定，
游程编码（省 6）；`zb_date` 只在终止行非空，稀疏（省 2）；
**`nib_upb`/`forgiven`/`defer_amt` 在 99.6% 的行上是零或空**（六档里 `forgiven > 0` 的是
**零笔**），稀疏对（省 12）；`upb` 是唯一稠密高熵列，对摊还计划取残差（省 2）。

另三条同样注册：**安静对索引本身可缓存**（六档 4,084 万对，int32 共 163 MB，
之后任何用安静月份的问题零启动，全年份规模下比换编码更划算）；**查询侧也按档并行**；
**分块 row group**，让一个问题可以流式扫而不必 materialize 整档。

# 6.2.10 quiet 过滤器更正：加 `upb[当前行] > 0`（陛下裁准，2026-08-16）

`quiet_pairs` 原本只要求 `upb[前一行] > 0`，对当前行只要求非缺失。
**于是「正 → 零」这一对能通过，`obs` 等于整个余额**，在比值直方图里被 clip 顶到上界。

**一笔真的还清了，余额归零是一个终止事件，按构造它不该算安静月份。**

- 旧口径由 `require_cur_positive=False` 保留，可逐位复现，因为 C8-1a 那一族跑的就是它。
- 返回值新增 `n_dropped_cur_zero`，即这一条**单独**移除的对数。它放在递延条件**之后**
  施加，否则会把递延条件本来就要拿走的对重复计数（先算得 856，改到最后算得 565）。
- `selftest` 现在**同时验两套**，并要求它们在夹具上**真的不同**，
  否则那道等价闸是空过的。夹具因此带上了首尾零 UPB 的形状（移除 565 / 18,896 对，约 3%）。

**【2026-08-16 同日更正，实测推翻】此处原写「污染落在高于众数那一侧，
C8-1a / C8-1c(b) / C8-1e 的上尾吃了它，而 p90 读 2.00–2.12 正是它的形状」。
那是推理不是测量，而且是错的。** 实测见 `results/b8_quiet_delta.md` 与 §6.2.10.2：
**这条更正在六档上一个对都没删掉**，所以从来没有污染，也没有上尾可吃。
那句「p90 读 2.00–2.12 正是它的形状」尤其坏：拿一个已有的数去追认一个未验证的机制，
看起来像证据，实际是巧合被征用。

**这条更正的地位因此是防呆不是修复。** 判据本身（余额归零是终止事件，不算安静月份）
不变，变的是它在真机上不承重。四个脚本重跑出来的数与更正前逐位相同，
R01 的双报由 `results/b8_quiet_delta.md` 结清，**不由那四份结果件结清**。

## 6.2.10.1 那道新加的自检第一次上真机就报了假绿，原因是夹具本身过期了

`selftest` 的夹具是**缓存**的（不删任何东西那条纪律的直接后果，跑过一次就留在盘上）。
`_synth` 改成会吐首尾零 UPB 的行之后，**跑过旧版的机器复用了旧档**，于是新那道检查读到
`cur-UPB-zero pairs removed : 0 of 23,389`。

**是那道检查自己抓住的**，因为它不止比较两套口径，还要求两套在夹具上**真的不同**。
**若它只比较不要求相异，一个过期夹具会让它永远空过且永远显示绿色。**

**修法，且不删任何东西**：夹具文件名带上生成器源码（`_synth` 加 `_reference`）的
八位哈希，`2098Q1_<tag>.zip`。生成器一改名字就变，过期的那份够不着，
但仍原样留在 `data/processed/fannie_core/_selftest/raw/` 里可以拿来看。

**登记为方法论一条：缓存的测试输入会过期，而等价性检查不要求两侧相异就是空过。**
这与 §6.2.9.1 是同一个形状，只不过那次的「碰巧前置条件」换成了「碰巧的缓存」。

**已重跑**：`b8_c8_1e_undermode.py`、`b8_c8_1f_freeze_recovery.py`、
`b8_omega.py probe`、`b8_0a_gate.py`（四个 import `b8_core`），**数与更正前相同**。
**不受影响**：`b8_c8_arithmetic.py`、`b8_c8_1c_contract_payment.py`、

**`max ratio` 是上限不是最大值。** 六个档、跨 2002 到 2019、不同利率不同余额、

算出来那是结构性上限：

```
上限 = (1 + (1+i)^(k+1)) / ((2+i)(k+1) + (1+i)^(k+1))
```

路径容差与符合度的界共用同一个 `1/B`，于是比值被路径筛选自己封顶。
k=1 时这个数在 3.75% 到 7.5% 的票面上都是 **0.4003 到 0.4005**，而六档的 `k` 中位数**全是 1**。

**后果，直说：符合度那一半在数学上被路径那一半蕴含，不携带独立信息。
闸的全部判别力在合格计数上。**

合格计数确实有判别力：90,115 个环里 53,781 个合格（约 60%），
而自检显示**月供估错 1% 会把终点移动 $30.55，对着 $0.0101 的容差**，三千倍。
月供错的话合格计数会塌到接近零，不是掉几个百分点。

**引用 B8-0a(i-a) 的地方，除 §6.2.8 那两条限定外，再加这一条：过它的是计数不是比值。**

## 6.2.11.2 两个容差同源，双报

第一轮用 `$0.05` 的路径容差配一个从半分推的符合度界，**后者严十倍**。

**那是构造缺陷，与判 PASS 还是 FAIL 无关。** 现在两个都从半分推：

| | |
|---|---|
| 路径容差 | `max(2h, h(1 + (1+i)^(k+1)))`，k=1/3/6 上是 0.0101 / 0.0101 / 0.0102 |
| 符合度的界 | `h((2+i)(k+1) + (1+i)^(k+1)) / 环内最小余额` |
| `h` | 半分，文件自己的 UPB 精度（纪律 5：判据里每个数都要有来源） |

**推导容差必须落在一分到一分二之间**，防止后面有人把它调松。

`experiments/b8_cmt_fetch.py`、`b8_cmt_sensitivity.py`（作废件）、`b8_cmt_sensitivity2.py`。
全文 `claude-docs/B8_曲线站与敏感度_v1.md`。

## 6.5.1 可得性：30 Yr 缺 47 个月，是曲线的性质不是下载工件

两个来源互校。**Treasury 的 30 Yr 缺 2002-03 到 2006-01 共 47 个月，FRED 的 DGS30 一月不缺。**

**判定不靠形状：CMT 是发行人定义的，发行人没发就是没有**，所以 FRED 在那里的数
必然是别的东西，构造未声明。形状是旁证：FRED 的 30 Yr 减 20 Yr 在窗口里从 −0.1265
走到 +0.2110、两头翻号，而两个来源的 20 Yr 逐月完全相等，所以那不是系统差。
**最大分歧 0.0507 落在 2002-02，正是停发那个月，那是拼接缝。**
其余各档最大差 0.0000 到 0.0054。20 Yr 两个来源都从 1993-10 起。

**取两个来源不是冗余**：只在一个来源缺的是下载工件，两个都缺才是曲线的性质，
一个来源分不出这两种。

## 6.5.2 B8 的实际需求

落在 30 Yr 缺口里的修改 **1,506 / 50,958，2.96%**。
**剩余期限超过 360 个月的占 62.5%，超过 420 个月的占 57.5%，超过 480 个月的占 3.2%。**

臣妾先看逐月 `max` 猜「多数是舍入、尾巴才是四十年期」，**错了**：
2002–2006 确实如此，但 HAMP 那 33,316 笔期限被延长到 420–480，整体压过来。
**又是拿局部读数外推到全体。**

## 6.5.3 第一次敏感度量错了对象，作废留档

量六种构造下 `log V` **单腿**的极差，读出 267 到 7,110 倍噪声底。
**错在这个量在 `r` 里精确约掉**：`r_month` 两条腿共用一个 `note_pct`、一个 `n_now`、
一个 `disc_pct`，而 `V = LP(bal,i,n)·A(d,n) + nib·(1+d)^(-bn)`，`LP` 对余额线性，
所以无递延余额时 `r = log(bal_now) − log(b_hat)`，`d` 不出现。

**臣妾说「修改当月期限变、两侧 `k` 不同、曲线进来」，对着实现是错的。**
这是从设计意图推实现行为，没读代码也没量。

## 6.5.4 第二次：抵消在真实行上断言，环和低八个数量级

无递延余额行的六构造极差 **3.553e-15**，六档相同，逐档 3,487 万到 909 万行。
**判据 `4·|log V|·eps = 1.243e-14`，实测是它的 0.29 倍。**
界有来源：`r` 是两个对数之差、`|log V|` 约 14，六构造只经过一个代数上精确约掉的
年金因子，剩下的只能是舍入。

**第一版这里用的是裸的 `0.0`，判了六个 DOES NOT CANCEL。那是无来源的数进了判据，
纪律 5 禁的正是这个，而本文件自己犯了。**
改判据之后**行数一个没变**，那是对的：阈值施加在已算好的 max spread 上，不进取数；
行数动了才说明阈值漏进了口径。

环和极差 p50 3.553e-15 到 5.329e-15、最大 4.974e-14，**对噪声底 6.5e-6 低八个数量级**。
**§16.11 的两个选择在这批数上动不了任何东西，但仍须在跑前写下来**，
否则下一个人不知道它是被看过还是被漏了。

## 6.5.5 新阻塞：递延腿估不出合同月供，且它挡住 B8-3

**两条后果，都必须随引用一起走：**

一、**§6.5.4 的「够不到」是在曲线能进来的那批之外量出来的。**
曲线唯一的门是递延气球项，而那扇门后面的贷款一个都估不出月供。

二、**`b8_fannie_slice.md` §14.4 的 B8-3 主路径对是「修改」对「递延」，两侧各占一个**，
递延那一侧现在没有月供估计量，**所以 B8-3 卡在这里，而 B8-3 是本站最强的那条**。

**一条待验的路，是推理不是结论**：递延不改月供（余额挪进零息气球，月供照旧），
若如此，从递延**之前**的安静月份估、再 carry 过去即可。
**本轮已经三次因为「推理没量」翻车，这条要量**，判据是递延前后可比月份上估计值是否一致。

## 6.6.2 待裁一：`t_M == t_B` 占 76.8%，leg 3 只在 10,449 个环上存在

**34,621 / 45,070 = 76.8% 的环，修改起始沿那一行本身就读 `00`。**
逐档 72.0% 到 87.4%，六档全在七成以上。**这不是边角，这是样本主体。**

§17.3 注册时要求这类环单独计数，那条要求是对的，
**但它当时估的量级错了：不是一小撮，是四分之三。**

**承重在哪：§2.1 的三顶点走法靠 `modified → current` 这条边闭合**
（`b₁ = 3 − 3 + 1 = 1`，§14.4 之后是五边四顶点 `b₁ = 2`），
而这条边在 76.8% 的环上**给零个月**。

§13.1 的规矩是「字段 42 的第一个 `Y` 标事件，`modified` 节点由分析者从那一刻
往后自己扛」。把它与 §14.3 的 leg 3 放一起读，那一行同时是
**再签约的事件行**与**回到履约的归位行**，两个标签落在同一个报送月上。

**能确定的三件：**

1. **环和不受影响。** §14.2 已定：跨腿归属是记账，闭环上的和与切法无关。
   **B8-1 不受这条影响。**
2. **受影响的是 §14.3 的 `ω₃` 诊断。** 它承诺 `ω₃ ≈ 0` 是量出来的不是假定的，
   而它只在 **10,449** 个环上可量，且那 10,449 是**被选择的**子样本
   （条件是「自愈比再签约晚至少一个月」）。
3. **`modified → current` 这条边确实被实现了，10,449 次，六档都有。**
   所以它不是一条空边，`b₁ = 2` 不因此塌掉。

**待裁的是命名与报送**，不是要不要跑：那 34,621 个环，是
（甲）leg 3 长度为零的修改三角，照旧进 B8-1；还是
（乙）另一类走法，与 leg 3 非空的那 10,449 分开报。
**两种都不改环和，改的是 `ω₃` 那一栏能写什么。**

**臣妾不裁这一条。** 一个能定它的便宜测量在 §6.6.5。

## 6.6.3 待裁二：`two_arms` 占候选 14.5%，而 §14.3 与 §14.4 对字段 63 说法不同

一段连续延滞内**同时**出现修改起始沿与递延起始沿的候选，
按 §17.4 从两臂都排除（走的是 `deferred → modified`，§14.4 的五条边里没有它）。

**排掉 8,073 个，占候选 14.5%，逐档 3.2% 到 19.7%，集中在 2006Q1 与 2007Q1。**

**冲突是文本层的，不是实现层的：**

| 出处 | 字段 63 在修改月被设起来，算什么 |
|---|---|
| **§14.3 leg 2** | 「principal moved to the deferred balloon in (63)」——**是修改这一腿的内容** |
| **§14.4** | 63 首次为正是 `deferred` 这一层的起始沿——**是另一条路径** |

**同一个字段，两节给了两个含义，而 8,073 个环挂在这上面。**

**这条不是 §17 造成的。** §17.4 忠实执行了 §14.4 的层逻辑；
是 §14.3 与 §14.4 本来就不一致，而在有计数之前它看不见。

**一个算术观察，只报不解释**（坑 17：不许拿已有读数追认未验证的机制）：
`two_arms` 与 §17.13 的 `tri_without_loop` 之比，
2006Q1 是 0.96、2007Q1 是 0.96，而 2002Q1 是 0.27。
**两档接近一、一档远不接近。** 这与「排除吃掉了那两档的大部分差」相容，
**与 2002Q1 不相容**，所以它不构成一个分解，只是一条要在分解时对上的约束。

**臣妾不裁这一条。** 判别式在 §6.6.5。

| **−1** | 递延额从余额里**挪出去**了，12 不含 108 |

## 6.6.15 O28 / O29 怎么裁：三件里两件由论证清掉，只有一件要量（2026-08-17）

陛下问的三件：有没有判别式、重跑会不会有不一样的结果、双报有没有记录价值。
**第二个问题本身就是判别式**，而且它比裁定便宜：先确定哪些数会变，再谈要不要留旧数。

按 SESSION_INIT 已定的规矩：**双报是透明性要求不是认识论要求**，
**「旧数值不值得看取决于它自己是什么」**。所以逐条问「旧数是什么」。

### 6.6.15.1 O28：判定**可证**不变，只有报出的数会动

`b8_0a_gate` 的判据是 **`pass = ratio_max < 1.0`**，而 `ratio_max` 是
**合格环上的最大值**（`np.nanmax(ratio)`）。

> **子集上的最大值不大于全集上的最大值。**
> 排掉带字段 108 的清洁自愈只会让 `ratio_max` 变小或不变。
> 而 B8-0a(i-a) 现在**六档全 PASS、`over 1` 全零**。
> **所以这个修复不可能把 PASS 翻成 FAIL。这是代数，不是测量。**

**会变的是**：合格计数 `ideal_ia`（下降）、`ratio_max`（下降或持平）、各分位。

**旧数值不值得看**：值得，**但只值一行**。旧 `ratio_max` 与新 `ratio_max` 的差
告诉你污染有没有压在最坏情形上；差得小说明那 5.92% 无害，差得大说明最坏的环就是递延。
**双报的内容是这一对数，不是重发一份结果件，更不是重跑下游**，
因为下游依赖的是判定而判定可证不变。

### 6.6.15.2 O29 方向一（不再整笔排掉带字段 63 的贷款）：**双报是空的**

**论证来自代码结构，不是数据：**

1. `quiet_pairs` 的排除是**逐贷款**的（`ok &= ~seen[cur]`，`seen` 由
   `cummax_within_loan` 给出）。
2. `contract_payments` 把 pair 按 `period[q["cur"]]` 分组，逐组取众数簇。
3. `contract_periods` 在**贷款边界**上必切（`b_loan`），**所以一个合同期只属于一笔贷款**。

> **把贷款 X 的 pair 加回来，只会进入贷款 X 自己的合同期。
> 任何其他贷款的估计值逐位不变。**

**旧数是什么**：与新数**在重叠样本上完全相同的同一批数**。
**补印它等于把同一份数印两遍。双报没有内容。**

**处置建议：改，不欠账。** R01 要守的是「让别人知道做过什么」，
而**这一条本身就是那个记录**。

### 6.6.15.3 O29 方向二（口径改成 `12 − 63 − 108`）：**唯一会改数的，影响面已被界定**

**先看不会变的那一大块，同样是代数**：对既没有字段 63 也没有字段 108 的贷款，
`12 − 63 − 108 = 12 − 0 − 0 = 12`。**逐位不变。**

**会变的只有**：带字段 108 的 **35,617 笔**，加上放开之后带字段 63 的 **11,128 笔**。

**而那 35,617 笔现在的数不是「旧口径下的数」，是判错的数。**
C11-1 已经判了 12 含 108，所以在这些贷款上把 12 当计息余额是**错**，
而 `contract_periods` 不在 108 的上升沿切，众数簇把递延前（对）与递延后（错）
的隐含月供混在一起取众数。

> **一个已经判错的数不构成证据，补印它没有记录价值。**
> **有价值的是另一个数：修复改动了多少笔、每笔改了多大。**
> 那是修复的**影响面**，它才是别人要知道的东西。

**影响面必须数出来，不能推**（坑 17）。**那就是 C12，本节唯一要跑的东西。**

### 6.6.15.4 C12：只量影响面，不判任何东西

`b8_core.quiet_pairs` 加一个开关 `ib_net`，**默认 `False` 且必须逐位复现现有结果**
（SESSION_INIT 教训四：「任何新参数或新开关，默认值必须逐位复现现有结果，

```

net      ib_net=True,  require_never_deferred=True     只改口径
open     ib_net=True,  require_never_deferred=False    口径加放开
```

**理由**：坑 18 那条纪律要守的是「输出能跟旧口径做差」，

### 6.6.17.2 一条随改动一起走的：**不要给 `contract_periods` 加字段 108 的边界**

C12 §3 那张「众数落在月份多的一侧」的表会诱导下一个人去加这个边界。**不加。**

**合同月供按构造不变，边界只会白掉覆盖率**。
**而口径改完之后这个理由更强** —— 混口径是口径造成的，
两侧都用 `12 − 63 − 108` 之后它自己就没了，加边界是治标。

`ib_net=False` 与 `require_never_deferred=True` 都**作为参数保留**，
与 `require_cur_positive` 同模式：**旧样本要能复现**，
而 C8-1a 全家的数是在那个口径下出的。**删开关等于让那些数不可复现。**

## 6.6.19 C13 的读法，**在跑之前钉死**：两个零息余额同时在的时候（2026-08-17）

### 6.6.19.1 这不是新缺陷，是 C11 的定义域边界

**C11 的判据 B 跑在 `quiet_pairs(require_never_deferred=True)` 的样本上**
（§6.6.14 跑的时候那还是默认），**那批贷款按构造没有字段 63**。
所以 C11-1 判的是

> **在没有字段 63 的贷款上，字段 12 含字段 108。**

**它没有判「字段 63 与字段 108 同时非零时，12 含不含两者之和」。**
C8-1 那边同理：它判的是 12 含 63，样本里没有 108 这一层。

**而 §14.1 的 `V` 要把计息余额写成 `12 − 63 − 108`，正需要那个没判过的东西。**
**这是用一条裁定用到它的定义域之外，不是那条裁定错了。**

### 6.6.19.2 人群与它的边界

同时带过字段 63 与字段 108 的贷款：**六档合计 1,276 笔**
（23 / 104 / 164 / 65 / 378 / 542，C10-4 的配对表）。

**量小是事实，不是判据。** §6.6.15.5 那条继续管着：
影响面只决定处置的代价，不决定要不要问。

### 6.6.19.3 判据：同一套摊还一致性，四个口径

月供 `P` 从**两个起始沿中较早那一个之前**的安静月份估，那时两个余额都是零、
四个口径重合，估计量中立（与 §6.6.13.1 判据乙同一个理由）。

然后在**两者都为正**的月份上比：

```
A      ib = 12
B63    ib = 12 − 63
B108   ib = 12 − 108
Bboth  ib = 12 − 63 − 108
```

| 读数 | 判 | `V` 怎么写 |
|---|---|---|
| **Bboth 最近** | 12 含两者 | 计息余额 `12 − 63 − 108`，气球 `63 + 108` |
| **B63 最近** | 12 只含 63 | 计息余额 `12 − 63`，字段 108 另算，**且与 C11 冲突，回头查** |
| **B108 最近** | 12 只含 108 | 计息余额 `12 − 108`，**且与 C8-1 冲突，回头查** |
| **A 最近** | 两者都不含 | **与 C8-1 和 C11 都冲突，回头查** |
| **四个都远离 `P`** | 定不了 | **这 1,276 笔排除并计数**，`V` 不在它们上面算。量小到可以排，**但必须印出来随引用走** |

**中间两支写着「回头查」而不是「改裁定」**：C8-1 与 C11 各自的样本里没有对方那一层，
所以冲突意味着**至少一个测量的定义域被超用了**，那要查不要改。

报 `|implied − P| / P` 的 p50 与 p90，四个口径并排，逐档加合计。

### 6.6.19.4 一条必须同时印的：两者的时间关系

C10-4 量出 63 与 108 **从不同行起跳**，但没量过它们**同时为正**的月份有多少。
**本节印这个数**：这 1,276 笔里，两者都为正的月份数，以及占它们全部月份的比。

**若那个数很小，第五支（排除）的代价就更小；若很大，判据的样本就更厚。**
**两个方向都要知道，所以印。**

所以不适用的那一项恒等于零。**三行读法不需要三条分支，也就没有分支可以写错。**

**分类唯一决定的是哪些贷款可以读**，不是怎么算。
这一点写进 `zero_interest_carrier` 的 docstring，因为它是本轮唯一
在结构上消掉一整类实现错误的地方，**而结构上消掉比测试出来更强**。

### 6.6.22.2 排除集是**并集**，比 C13 的 1,276 只多不少

C13 数 1,276 笔用的是**两列的上升沿**。上升沿要求同一笔贷款里存在前一行，
**所以一笔在首行就带着字段 63 的贷款根本没有上升沿**（坑 1，左截断），
而它的字段 12 一样是不可识别的。

`zero_interest_carrier` 排的是

```
both_edges（C13 的谓词，逐字复现）  ∪  ever_both_positive（同一个月两者皆正）
```

**两半分开计数并分开印**（`both_edges` / `ever_both_positive` /
`excluded` / `excluded_beyond_c13`）。**这是把 C13 的处置应用到一个不小于
它的集合上，永远不会更小。** 两者差多少是**读出来的数**，不是假设。

**注册时的缺口照记**：§6.6.20.6 写的是「两者都有（1,276 笔）」，
没有写这个数是按哪个谓词数的。**是实现的时候才发现有两个谓词。**

## 6.6.23 第二块第二节：环装配，以及 `r_month` 在修改当月一直是错的（2026-08-17）

### 6.6.23.1 **`V̂` 一直是按新合同定价的，而那就是 leg 2**

§14.2 的原文：`V̂(t)` 是「the **unchanged** contract carried one month forward
from `t−1`: same note rate, balance reduced by the scheduled principal payment,
`(17)` reduced by one, same deferred balloon」。

`r_month` 两条腿**共用 `note_pct` 与 `n_now`**。

**在安静月份上利率不动、`n_now == n_prev − 1`，两种读法逐位相同**，
所以 P1 到 P5 在两种读法下全过，这个函数从写出来到现在没有任何一个测试碰过它们分家的地方。

**它们分家的地方是修改当月，而修改当月是 leg 2 唯一的一个月。**
C10-4 量过：字段 63 的起始沿上利率动 46.1%、期限动 84.2%。

量一下差多少（P8，2% 降息 + 120 个月展期）：

```
旧读法   r = +1.670289e-03
新读法   r = -1.791568e-01
```

**差两个数量级，而且符号反了。** 旧读法说这次修改让家庭略微更重，
新读法说是一次大幅减负。§14.3 写的「leg 2 是 dominant term」，
所以这个缺陷不是落在边角上，**它落在整个站要测的那个量上**。

**修法**：`r_month` 加三个 `_prev` 参数（`note_prev` / `n_prev` /
`balloon_n_prev`），**省略时逐位复现旧行为**，这样四条闸的性质仍可跨这次改动比较；
`row_residuals` 三个全传。

### 6.6.23.2 反事实要的月供是**前一行**的

同一条：`V̂(t)` 是 `t−1` 的合同往前推一个月，**所以它要的是修改前的月供**，
而那笔月供住在**前一个合同期**里。

原来的实现要求「本行有已知月供」。在修改当月，本行属于修改后的合同期，
**于是要么用错了月供，要么把修改当月整个筛掉，而那个月就是 leg 2**。

现在的条件是**前一行有已知月供**。副产物：`r(t)` 在合同期边界上**是可算的**，
原来那条「窗口跨边界就不算」的筛子是错的 —— 修改臂的窗口按构造就跨边界（§17.10），
那条筛子等于把整条修改臂判成不可测。

### 6.6.23.3 §17.11 那条恒等式，**在前缀和实现下是空的**

§17.11 要求断言 `leg1 + leg2 + leg3 == ω(环)`，理由写着「它能抓住窗口实现的错位」。

四个量都从同一个前缀和数组来：

```
ω     = P[t_B+1] − P[t_A+1]
leg1  = P[t_M]   − P[t_A+1]
leg2  = P[t_M+1] − P[t_M]
leg3  = P[t_B+1] − P[t_M+1]
```

**三条腿望远镜式抵消，`t_M` 取什么都成立** —— 错一行、错十行、
甚至属于另一笔贷款都成立。**这条断言测的是浮点加法器。**

**处置：断言留着（它注册过，而且确实能抓住前缀和或范围助手本身写坏），
另加一个真的能干那件事的。** `replay` 从窗口下标出发、**逐月用 Python 重新求和**，
和向量化的答案比。自检里把 `t_M` 故意挪一行：**恒等式照样成立，`replay` 报 1 处不符。**

**这是对 §17.11 的更正，按更正立账**：那一节给的理由不成立，要求本身留着，
它想干的那件事现在有东西真的在干。

### 6.6.26.4 第四轮：三次人群选择推它三个数量级，所以问题在统计量

**陛下问的「1% 扛 99.98% 有没有道理」，答案是：对这个分布有道理，
而这恰恰说明方差不该是那个统计量。** 顺带排除掉的一条：巨额贷款不是机制。
`V` 的月供线性于余额，余额乘 λ 则 `V` 乘 λ，**`ω = log V − log V̂` 完全不变**。

### 6.6.26.6 裁定：B8-1 的判据换成 MAD 比值，旧口径并排留着

```
MAD 比值 = MAD(信号臂的 ω) / MAD(清洁自愈臂的 ω)
2019Q1： pooled 6,501 / 修改臂 50,680 / 递延臂 4,931
```

直白说：**典型的清洁自愈返回 `ω ≈ 2.7e-6`，典型的修改环返回 `ω ≈ 1.4e-1`，
差五万倍**，而这个数在人群选择与样本量下都不动。

**换判据的理由是实测的不是偏好**：`√Z/√N` 在三次站得住的人群选择下走过
1.45 → 54.70 → 1,008，而底的方差本身不收敛。
**一个能被人群定义推三个数量级的比值不是信噪比。**

**保留意见，写清楚**：Theorem 3 是**方差**分解，换成 MAD 就不再是那条定理
要的那个量。但一个不收敛的方差也检验不了方差分解。所以正确的写法是：
**`Z` 估得很好（4.61e-2，收敛），而底不是一个数，是一个中心明确（2.7e-6）
而尾巴无界的分布。** 问「信号在不在噪声之上」，中心是对的比较；
问「多少环与测量误差不可区分」，那要尾巴，**是另一个问题，另记**。

**四轮里有三轮的结论是「跑之前不可能知道」。**
第一轮不跑不知道底是尾部统计量；第二轮不跑不知道尾巴是结清而不是注册过的
那个嫌疑人；第四轮不跑不知道方差本身不收敛。
**§18.5 那张跑前映射表在第一轮之后就有一条指错了方向**
（`M < N` 判「回头查格键」，而实测 `M ≈ Z`，`M < N` 出现的地方恰好是
`Z < N` 的地方，与格键无关）。

这就是 §18.5 改成「可改的记录」而不是承诺的实证支持。**留下的价值不是
它约束了什么，是预期与现实的差**，而这一节的差有四条。

### 6.6.27.3 P4 早就知道，而 §14.5 的措辞把它盖住了

臣妾找底的时候读的是 §14.5 那句，于是把一个确定量当成了噪声。**更正在 §18.8。**

### 6.6.27.4 顺带：这是 `ω` 构造至今最强的一次检验

§2.4 那一列不是在验底，**它同时验了整条流水线**。
`rows_for_V` → `disc_of_row` → `r_month`（带曲线、带气球、带 `_prev` 三个参数）
→ `loop_sums`（§17 窗口），**逐档在 24,033 到 144,941 个环上复现一个闭式解析预测，

而且它走的是**另一条代码路径**：B8-0a(i-a) 用的是流式对数余额和（无曲线无气球），
这里用的是完整的 `r_month`。**两条独立实现落在同一个解析解上。**

### 6.6.27.5 裁定与保留
